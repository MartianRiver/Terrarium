Every game in a scored job now starts from its own world with its own random numbers, so game i of a job with seed S is the same game in a 32-, 64- or 128-game job, and food eaten or a tree moved in one arena no longer changes what is drawn in another (until now all arenas shared one stream, so more games, or a different brain playing beside, shifted every world). A reset arena also starts exactly as a new one does: its physics is rebuilt (the old space carried contact leftovers that moved the first ticks), smell draws its walls on the first step instead of keeping the last game's, and a new world places its food patches after its blocks move as a reset does. A brain's sampled action noise is per game too, from the game's seed and number, where it used to start from the same fixed seed in every scoring run. Scores from before this and after aren't comparable game for game; they are still fair estimates, but a change between the two can't be put down to training alone. Training runs reset the same way and play different games from the same seeds.

Scoring says what didn't happen. The tree games give every game's `start_fell_back` (the Terrikins couldn't be ringed round the trunk and stayed at the nest spawn), `moves_failed` (the tree found nowhere to move to; both also logged as warnings) and `tree_seen_from_home` (at the start the trunk is within the rays' range of the nest's middle with a clear line, so it can be found without remembering), so an analysis can drop or split those games. Wiping a brain's notes on unloading (`--wiped-on-event`, tree-home) now fires only when an apple is stored in the Terrikin's own nest, not when it eats from its crop there, and `walked` no longer counts the burrow's jump back to the nest's middle as walking. Score jobs take `wiped_on_event = true` (worker version 13; older workers aren't given such a job).
